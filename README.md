
# PowerShell Network Troubleshooting Toolkit

## Project Overview

This project demonstrates how PowerShell can help an IT Support technician perform selected network diagnostics and record the results in a structured CSV report.

The project uses a fictional company, Mahlangu Business Solutions, and a simulated Help Desk scenario in which an employee cannot access a website.

The toolkit collects diagnostic evidence and recommends further checks. It does not automatically change network settings.

## Business Scenario

An employee reports:

"My laptop is connected to Wi-Fi, but I cannot open the company website."

The IT Support technician needs to investigate whether the issue may involve network adapter status, IPv4 configuration, gateway configuration, DNS resolution, destination reachability, or TCP connectivity to the requested service.

## Features

- Checks whether network adapters report an Up state.
- Inspects selected IPv4, default gateway, and DNS configuration indicators.
- Tests reachability to a selected destination.
- Checks DNS name resolution for a selected hostname.
- Tests TCP connectivity to a specified host and port.
- Generates a CSV report containing statuses, findings, and recommendations.
- Distinguishes `Pass`, `Review`, and `UnableToAssess` outcomes.
- Avoids recording actual adapter IP addresses in the report.
- Includes automated tests for report structure and expected diagnostic checks.
- Performs read-only diagnostics without changing network settings.

## How to Run the Diagnostics

Open PowerShell in the project root directory.

### 1. Run the default diagnostic checks

```powershell
.\scripts\Invoke-NetworkDiagnostics.ps1
```

The default checks use:

- `1.1.1.1` for destination reachability.
- `example.com` for DNS name resolution.
- `example.com` on TCP port `443` for service connectivity.

These are public example destinations, not company-specific internal systems.

### 2. Use different diagnostic targets

The script supports custom targets, hostnames, and TCP ports. For example:

```powershell
.\scripts\Invoke-NetworkDiagnostics.ps1 `
    -ConnectivityTarget "1.1.1.1" `
    -DnsName "example.com" `
    -TcpHost "example.com" `
    -TcpPort 443
```

Use only destinations you are authorised to test.

### 3. Run the automated tests

```powershell
.\tests\Test-NetworkDiagnosticsReport.ps1
```

The test suite runs the real diagnostic checks, verifies the generated report and required columns, checks that all seven diagnostic categories are present, and validates report statuses and recommendations.

## Safety and Limitations

- The toolkit performs diagnostic checks only.
- It does not reset adapters, flush DNS, change firewall rules, or modify IP configuration.
- A failed ping does not necessarily mean that a destination or network is unavailable; ICMP traffic may be blocked.
- DNS results depend on the hostname, resolver, and network environment.
- A failed TCP connection may be caused by routing, filtering, service availability, or an incorrect target.
- A successful diagnostic run does not guarantee that all network services are functioning correctly.
- Public reports should not contain unnecessary private IP addresses, MAC addresses, internal hostnames, usernames, or other identifying details.
- The generated report should be reviewed before publication because network and system details can change.
